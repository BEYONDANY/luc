# LEC-1 认证中心设计与方案对比

## 目标

实现一个可用的认证中心，覆盖：

1. 用户登录 / 退出 / 当前会话查询
2. 管理员用户管理（创建、启停、改角色、重置密码）
3. 本地可运行、可测试、可审查的交付物

## 方案对比

### 方案 A — 单体服务（Express + SQLite + 静态管理台）

- 优点：依赖少、启动快、单进程交付、适合首版闭环
- 缺点：前后端未分离部署；后续若要做 SSO/多租户需演进
- 适用：快速验证登录与用户管理主路径

### 方案 B — 分离式（API 服务 + 独立 SPA + 外部 Postgres）

- 优点：扩展性更好，便于后续接入 IdP / 多端
- 缺点：首版运维与脚手架成本更高，空仓库冷启动慢
- 适用：已有基础设施与明确多服务边界时

## 综合结论（本心跳采用）

采用 **方案 A** 落地 MVP，并保留清晰 API 边界（`/api/auth/*`、`/api/users/*`），便于后续拆分为方案 B。

## 功能清单（已实现）

- `POST /api/auth/login`：用户名密码登录，返回 JWT，并写 HttpOnly Cookie
- `POST /api/auth/logout`：清理 Cookie
- `GET /api/auth/me`：当前用户
- `GET/POST/PATCH /api/users`：管理员用户管理
- `POST /api/users/:id/reset-password`：重置密码
- 管理台 UI：登录页 + 用户列表/创建/启停/角色/重置密码
- 默认管理员种子账号（可用环境变量覆盖）
- 自动化测试：登录失败/成功、创建与禁用用户

## 默认凭据（仅开发）

- 用户名：`admin`
- 密码：`Admin123!`

生产环境务必设置 `JWT_SECRET` 与强管理员密码。
